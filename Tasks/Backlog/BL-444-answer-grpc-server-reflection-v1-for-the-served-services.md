# BL-444 — Answer gRPC server reflection v1 for the served services

## Goal

The gRPC server answers `grpc.reflection.v1.ServerReflection/ServerReflectionInfo` (and v1alpha if
BL-441's ADR says so). It lists its services and returns the serialized `FileDescriptorProto`s that describe
them and their dependencies, so a client with no `.proto` file can call them.

## Context

- Decision: BL-441's ADR, decision 9.
- grpc/grpc `doc/server-reflection.md` and `reflection/v1/reflection.proto`: `ServerReflectionRequest`
  (`list_services`, `file_by_filename`, `file_containing_symbol`, `file_containing_extension`,
  `all_extension_numbers_of_type`) and `ServerReflectionResponse` (`list_services_response`,
  `file_descriptor_response` with the transitive files, and `error_response` with a gRPC status code).
- `descriptor.proto`: the `FileDescriptorProto`, `DescriptorProto`, `FieldDescriptorProto`,
  `ServiceDescriptorProto` and `MethodDescriptorProto` fields used. The descriptors are built from code, with
  protobuf bytes from BL-442's codec, and never generated by `protoc` at build time.
- Reflection is a bidirectional-streaming method: several requests on one stream, one response each.

## Acceptance criteria

- [ ] Named tests show:
      - `list_services` names the built-in service and the reflection service;
      - `file_containing_symbol` for the built-in service returns its file, which decodes to the expected
        service, methods and message fields;
      - `file_by_filename` for an unknown file returns `error_response` `NOT_FOUND` (5);
      - three requests on one stream get three responses in order.
- [ ] `dotnet build -warnaserror` is clean, the fast tests are green, and the library keeps 100% line and branch
      coverage.
