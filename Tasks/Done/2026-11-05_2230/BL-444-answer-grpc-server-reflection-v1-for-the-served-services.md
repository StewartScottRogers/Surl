# BL-444 — Answer gRPC server reflection v1 for the served services

## Goal

The gRPC server answers `grpc.reflection.v1.ServerReflection/ServerReflectionInfo` (and v1alpha if
BL-441's ADR says so). It lists its services and returns the serialized `FileDescriptorProto`s that describe
them and their dependencies, so a client with no `.proto` file can call them.

## Context

- Decision: BL-441's ADR, decision 9.
- grpc/grpc `doc/server-reflection.md` and `reflection/v1/reflection.proto`: `ServerReflectionRequest`
  (`list_services`, `file_by_filename`, `file_containing_symbol`, `file_containing_extension`,
  `all_extension_numbers_of_type`) and `ServerReflectionResponse` (`list_services_response`,
  `file_descriptor_response` with the transitive files, and `error_response` with a gRPC status code).
- `descriptor.proto`: the `FileDescriptorProto`, `DescriptorProto`, `FieldDescriptorProto`,
  `ServiceDescriptorProto` and `MethodDescriptorProto` fields used. The descriptors are built from code, with
  protobuf bytes from BL-442's codec, and never generated by `protoc` at build time.
- Reflection is a bidirectional-streaming method: several requests on one stream, one response each.

## Acceptance criteria

- [x] Named tests show:
      - `list_services` names the built-in service and the reflection service;
      - `file_containing_symbol` for the built-in service returns its file, which decodes to the expected
        service, methods and message fields;
      - `file_by_filename` for an unknown file returns `error_response` `NOT_FOUND` (5);
      - three requests on one stream get three responses in order.
- [x] `dotnet build -warnaserror` is clean, the fast tests are green, and the library keeps 100% line and branch
      coverage.

## Notes

- Built per ADR-0116 decision 9: `ServerReflectionService` (v1 and v1alpha, answered alike) over
  `ProtoFileDescriptor` and its parts, plus `ServerReflectionFiles` (both `reflection.proto` files) and
  `EchoService.File`. Tests in `ServerReflectionServiceTests` (end to end through `GrpcStreamHandler` on
  HTTP/2 frames written by hand) and `ProtoFieldDescriptorTests`:
  `ServerReflectionInfo_ListServices_NamesTheBuiltInServiceAndBothReflectionServicesInOrdinalOrder`,
  `ServerReflectionInfo_FileContainingSymbolForTheBuiltInService_ReturnsEchoProtoWithItsServiceMethodsAndFields`,
  `ServerReflectionInfo_FileByFilenameUnknown_IsErrorResponseNotFoundAndTheStreamStillEndsOk`,
  `ServerReflectionInfo_ThreeRequestsOnOneStream_GetThreeResponsesInOrder`.
- Choice: `repeated` fields in `reflection.proto` (`file_descriptor_proto`, `extension_number`,
  `service`) carry `LABEL_REPEATED`, as descriptor.proto requires; ADR-0116 decision 9's "label
  `LABEL_OPTIONAL`" was written for the Echo file, whose fields are all singular. Documentation is outside
  this task's `touches`, so the ADR wording is left for a docs pass.
- Choice: `client_streaming`/`server_streaming` are written only when true, as protoc leaves a bool at its
  default out; `valid_host` is left out when the request has no `host` (proto3 default).
- Choice: `all_extension_numbers_response`'s `base_type_name` is the type name as the client wrote it
  (leading dot kept); the lookup ignores a leading dot.
- Choice: no `dependency` support in `ProtoFileDescriptor`: the three files import nothing (ADR-0116
  decision 9), so each file is its own transitive closure. A file with imports adds it then.
- Coverage (Measure-CodeQuality, grpc library): 100% line, 100% branch. Three members flagged on
  complexity (`GrpcTimeout.ReadValue`, `ProtobufReader.ReadField`, `EchoRequest.Read`) predate this task;
  none of the new members is flagged.
- Wiring the reflection service into `surl` is BL-445's.
