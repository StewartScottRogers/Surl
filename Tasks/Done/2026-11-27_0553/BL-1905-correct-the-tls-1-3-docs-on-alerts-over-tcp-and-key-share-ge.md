# BL-1905 — Correct the TLS 1.3 docs on alerts over TCP and key share generator draws

## Goal

The docs on `TlsAlertException`, `TlsKeyExchange` and `Tls13ServerStream.AcceptAsync`, and the library's
`CLAUDE.md`, match what the code sends on each transport and what it draws from the injected generator.

## Context

Found by BL-1895 on 2026-11-27. Comments and prose only. No store, event or fault changes. BL-1895's
`TlsServerHandshake` remarks give the draw order; BL-1894 corrects the other QUIC-only statements in the same
`CLAUDE.md`.

- `TlsAlertException.cs`: the summary describes QUIC only; `Surl.Tls13Stream` sends the alert over TCP.
- `TlsKeyExchange.cs`: the `Agree` doc omits the x448 and curveSM2 private keys, including the curveSM2 half of
  curveSM2MLKEM768. The ffdhe `<summary>` sits above `AgreeCurveSm2`, so that method has two summaries and
  `AgreeFiniteField` has none.
- `Surl.Tls13.UnitLibrary/CLAUDE.md`: no sentence states the curveSM2 key draw for curveSM2MLKEM768.
- `Tls13ServerStream.cs`: the `AcceptAsync` `random` parameter doc says "the server random and key shares", but a
  NIST curve key is generated by the base class library.

## Acceptance criteria

- [x] `TlsAlertException`'s summary says how the alert reaches the peer over QUIC and over TCP.
- [x] `TlsKeyExchange.Agree`'s summary names every draw from `random`, and `AgreeCurveSm2` and `AgreeFiniteField` each have exactly one summary.
- [x] `CLAUDE.md` states that curveSM2MLKEM768 draws ML-KEM's m and then a 32-byte curveSM2 private key.
- [x] The `random` parameter doc of `Tls13ServerStream.AcceptAsync` excludes NIST curve keys.
- [x] The diff to the three `.cs` files changes comment lines only, and `dotnet build` has no warnings.
