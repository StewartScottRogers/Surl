# Surl.Cryptography.BcryptPbkdf.UnitLibrary

Holds `BcryptPbkdf`: OpenSSH's `bcrypt_pbkdf` (openssh-portable `openbsd-compat/bcrypt_pbkdf.c`,
tag `V_9_9_P1`), the key derivation of `openssh-key-v1` private keys written with a
passphrase (KDF name `bcrypt`, ADR-0051). `DeriveKey` takes the passphrase, the salt, the
rounds and the output span, and refuses with an argument exception every input the C
function refuses: an empty passphrase, an empty salt or one longer than 1 MiB, an empty
output or one longer than 1024 bytes, and rounds below 1. Its core, Blowfish with bcrypt's
salted key schedule, is `Surl.Cryptography.Blowfish.UnitLibrary`'s `Blowfish`, the one
library this one references (ADR-0061); inside this namespace the type is written
`Blowfish.Blowfish`, because `Blowfish` alone names the namespace
`Surl.Cryptography.Blowfish`. The base class library has no bcrypt_pbkdf, so it is
hand-built here. SHA-512 is the BCL's `SHA512`. Reading `openssh-key-v1` files is
`Surl.Protocol.Ssh`'s work (BL-223), not this library's.

Protocol servers may reference it as a horizontal library. Bytes in, bytes out: never open
a socket or a file, and never read a clock.

Every function is tested against published vectors, with the source cited beside each:
the vectors "generated by the reference implementation from OpenBSD" in Go's
`golang.org/x/crypto/ssh/internal/bcrypt_pbkdf` tests for the derivation and its inner
bcrypt hash. Blowfish's own vectors are tested in `Surl.Cryptography.Blowfish.UnitTests`.
Copying bcrypt_pbkdf and its tests from the Curl port is allowed: code is not a verdict,
and no expected value comes from it (ADR-0003).
