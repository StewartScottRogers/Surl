# Surl.Cryptography.BcryptPbkdf.UnitLibrary

Holds `BcryptPbkdf`: OpenSSH's `bcrypt_pbkdf` (openssh-portable `openbsd-compat/bcrypt_pbkdf.c`,
tag `V_9_9_P1`), the key derivation of `openssh-key-v1` private keys written with a
passphrase (KDF name `bcrypt`, ADR-0051). `DeriveKey` takes the passphrase, the salt, the
rounds and the output span, and refuses with an argument exception every input the C
function refuses: an empty passphrase, an empty salt or one longer than 1 MiB, an empty
output or one longer than 1024 bytes, and rounds below 1. The internal `BlowfishState` is
Blowfish (Schneier, 1993) with the key schedules of OpenBSD's `blf.c`, the standard one and
the salted one bcrypt's "eksblowfish" adds; `BlowfishPiDigits` holds its initial P-array and
S-boxes. The base class library has neither Blowfish nor bcrypt_pbkdf, so both are hand-built
here. SHA-512 is the BCL's `SHA512`. Reading `openssh-key-v1` files is `Surl.Protocol.Ssh`'s
work (BL-223), not this library's.

It references nothing (ADR-0051); protocol servers may reference it as a horizontal
library. Bytes in, bytes out: never open a socket or a file, and never read a clock.

Every function is tested against published vectors, with the source cited beside each:
Eric Young's Blowfish ECB table (Schneier's `vectors-2.txt`) for the cipher, and the
vectors "generated by the reference implementation from OpenBSD" in Go's
`golang.org/x/crypto/ssh/internal/bcrypt_pbkdf` tests for the derivation and its inner
bcrypt hash. Copying Blowfish, bcrypt_pbkdf and their tests from the Curl port is allowed:
code is not a verdict, and no expected value comes from it (ADR-0003).
