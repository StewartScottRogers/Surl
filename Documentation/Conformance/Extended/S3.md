# S3 requirement matrix

The server-side requirements `Surl.Extended.Protocol.S3` answers, for the `s3` scheme (ADR-0083
decision 9). Written from the Amazon S3 API Reference
(<https://docs.aws.amazon.com/AmazonS3/latest/API/>) and the Amazon S3 User Guide pages
[ADR-0108](../../Planning/Decisions/ADR-0108-how-the-s3-server-answers-s3.md) decides by, never from
the Curl port's client matrix. Each row binds the server; "Covered by" names the task that proves
it, until that task replaces its ID with the named test, or says why the row needs no test.

The pages state few requirements in RFC keywords, so each response element a server writes, each
rule of a page and each error a server owes is a row. IDs are `S3:<Page>-<n>` for an API Reference
or User Guide page, `S3:SigV4-<Part>-<n>` for the SigV4 pages, and `S3:Surl-<Decision>-<n>` for a
rule ADR-0108 adds where the pages leave the server a choice.

## Errors and common headers ("Error responses", "Common Response Headers")

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:ErrorResponses-1 | MUST | A failure is a 3xx, 4xx or 5xx status with an `application/xml` `Error` body holding `Code`, `Message`, `Resource` and `RequestId`. | BL-418 |
| S3:ErrorResponses-2 | MUST | Each code is sent with the status the "List of error codes" table gives it (ADR-0108 decision 1.1's table). | BL-418 |
| S3:ErrorResponses-3 | MUST | `NoSuchKey` carries `Key`, `NoSuchBucket` carries `BucketName`, `InvalidArgument` carries `ArgumentName` and `ArgumentValue`. | BL-418 |
| S3:ErrorResponses-4 | MUST | A `HEAD` error has its status and no body. | BL-418 |
| S3:CommonResponseHeaders-1 | MUST | Every answer carries `x-amz-request-id`, the same value as the error body's `RequestId`. | BL-418 |
| S3:Surl-Errors-1 | MUST | `Code` and `Message` are fixed text; `Resource` and the extra elements are the only client bytes echoed, XML-escaped and cut to 1024 bytes. | BL-418 |
| S3:Surl-Errors-2 | MUST | `SignatureDoesNotMatch` carries no `StringToSign` or `CanonicalRequest`. | BL-420 |
| S3:Surl-Operations-1 | MUST | Any request ADR-0108 decision 1 does not list is `501 NotImplemented`, judged after authentication. | BL-418 |
| S3:Surl-Operations-2 | MUST | CreateBucket, DeleteBucket, CopyObject and ListObjects version 1 are `501 NotImplemented`. | BL-418 |

## Addressing ("Virtual hosting of buckets", "Bucket naming rules")

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:VirtualHosting-1 | MUST | A path-style request names the bucket as the path's first segment, `/<bucket>/<key>`; `/` is the service. | BL-418 |
| S3:VirtualHosting-2 | MUST | `Host: <bucket>.<domain>` names the bucket and the whole path is the key. | BL-419 |
| S3:VirtualHosting-3 | MUST | A bucket name holding dots is read whole from the host name. | BL-419 |
| S3:Surl-Addressing-1 | MUST | The domains are the listen URL's DNS host, `localhost`, `s3.amazonaws.com` and `s3.<region>.amazonaws.com`; any other `Host` is path style. | BL-419 |
| S3:Surl-Addressing-2 | MUST | No region is checked and no `PermanentRedirect` is sent. | BL-419 |

## Buckets and keys on the store ("Object key naming guidelines"; ADR-0100 decision 2)

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:ObjectKeys-1 | MUST | The key is percent-decoded once from the path, as UTF-8. | BL-418 |
| S3:ObjectKeys-2 | MUST | A key over 1024 UTF-8 bytes is `400 KeyTooLongError`. | BL-418 |
| S3:Surl-Store-1 | MUST | A bucket is a top-level folder of the shared content store; a top-level file and `.surl` are not buckets. | BL-418 |
| S3:Surl-Store-2 | MUST | A key the store cannot hold is `400 InvalidArgument` on a write and `404 NoSuchKey` on a read. | BL-419 |
| S3:Surl-Store-3 | MUST | A key conflicting with a folder or file of the other kind is `409 InvalidArgument`. | BL-419 |
| S3:Surl-Store-4 | MUST | A file another protocol wrote is served with the metadata index's default `Content-Type` and ETag. | BL-419 |
| S3:Surl-Store-5 | MUST | A bucket or key the caller may not read is `404 NoSuchBucket` or `NoSuchKey`; a write it may not make is `403 AccessDenied`. | BL-419 |
| S3:Surl-Store-6 | MUST | A zero-byte PutObject of a key ending in `/` creates the folder; a non-empty one is refused. | BL-419 |

## GetObject and HeadObject

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:GetObject-1 | MUST | `GET /<bucket>/<key>` answers `200` with the object's bytes. | BL-418 |
| S3:GetObject-2 | MUST | The answer carries `Content-Length`, `Content-Type`, `ETag`, `Last-Modified`, `Accept-Ranges: bytes` and each stored header and `x-amz-meta-*`. | BL-418 |
| S3:GetObject-3 | MUST | One `Range: bytes=` range is `206` with `Content-Range`; an unsatisfiable one is `416 InvalidRange`. | BL-418 |
| S3:GetObject-4 | MUST | Several ranges are ignored and the whole object served with `200`. | BL-418 |
| S3:GetObject-5 | MUST | `If-Match` failing and `If-Unmodified-Since` failing are `412 PreconditionFailed`. | BL-418 |
| S3:GetObject-6 | MUST | `If-None-Match` matching and `If-Modified-Since` not modified are `304`. | BL-418 |
| S3:GetObject-7 | MUST | `If-Match` true with `If-Unmodified-Since` false serves; `If-None-Match` false with `If-Modified-Since` true is `304`. | BL-418 |
| S3:GetObject-8 | MUST | A missing key is `404 NoSuchKey`; a missing bucket `404 NoSuchBucket`. | BL-418 |
| S3:GetObject-9 | MAY | `partNumber` reads one part of a multipart object. | n/a: `501 NotImplemented` (ADR-0108 decision 1) |
| S3:HeadObject-1 | MUST | `HEAD` answers GetObject's head with no body. | BL-418 |

## PutObject

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:PutObject-1 | MUST | `PUT /<bucket>/<key>` stores the body and answers `200` with its `ETag`, the quoted hex MD5. | BL-419 |
| S3:PutObject-2 | MUST | A `PUT` with no `Content-Length` and no decoded length is `411 MissingContentLength`. | BL-419 |
| S3:PutObject-3 | MUST | `Content-MD5` not matching the body is `400 BadDigest`; one that is not base64 of 16 bytes `400 InvalidDigest`. | BL-419 |
| S3:PutObject-4 | MUST | `Content-Type`, `Content-Encoding`, `Content-Disposition`, `Cache-Control`, `Content-Language` and `x-amz-meta-*` are stored and returned by GetObject and HeadObject. | BL-419 |
| S3:ObjectMetadata-1 | MUST | User metadata past 2 KiB is `400 MetadataTooLarge`. | BL-419 |
| S3:PutObject-5 | MUST | A `PUT` overwrites an existing object. | BL-419 |
| S3:PutObject-6 | MUST | `x-amz-checksum-crc32`, `-crc32c`, `-sha1` and `-sha256` are checked when sent (`400 BadDigest`) and echoed. | BL-711 (`S3ObjectBodyReaderTests`, `S3ChecksumTests`) |
| S3:PutObject-7 | MAY | `x-amz-checksum-crc64nvme`. | n/a: `501 NotImplemented` (ADR-0108 decision 4.5) |

## DeleteObject, HeadBucket and ListBuckets

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:DeleteObject-1 | MUST | `DELETE /<bucket>/<key>` removes the object and answers `204`, also for a key that does not exist. | BL-712 |
| S3:HeadBucket-1 | MUST | `HEAD /<bucket>` is `200` for a bucket the caller may read and `404` with no body otherwise. | BL-712 |
| S3:ListBuckets-1 | MUST | `GET /` answers `ListAllMyBucketsResult` with `Owner` and each `Bucket`'s `Name` and `CreationDate`. | BL-712 |
| S3:ListBuckets-2 | MUST | Only buckets the caller may read are listed. | BL-712 |

## ListObjectsV2

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:ListObjectsV2-1 | MUST | `GET /<bucket>?list-type=2` answers `ListBucketResult` in the `http://s3.amazonaws.com/doc/2006-03-01/` namespace, its elements in the page's order. | BL-419 |
| S3:ListObjectsV2-2 | MUST | Keys are listed in ascending UTF-8 byte order. | BL-419 |
| S3:ListObjectsV2-3 | MUST | `prefix` limits the listing to keys that begin with it. | BL-419 |
| S3:ListObjectsV2-4 | MUST | With `delimiter`, keys sharing a prefix up to the first delimiter after `prefix` roll up into one `CommonPrefixes`. | BL-419 |
| S3:ListObjectsV2-5 | MUST | `max-keys` defaults to 1000, above 1000 is 1000, and bounds `Contents` and `CommonPrefixes` together; `KeyCount` counts both. | BL-419 |
| S3:ListObjectsV2-6 | MUST | A truncated page has `IsTruncated` true and `NextContinuationToken`; the token resumes after the last entry returned. | BL-419 |
| S3:ListObjectsV2-7 | MUST | `start-after` begins after that key; `continuation-token` wins over it. | BL-419 |
| S3:ListObjectsV2-8 | MUST | `encoding-type=url` percent-encodes keys and prefixes; another value is `400 InvalidArgument`. | BL-419 |
| S3:ListObjectsV2-9 | MUST | `fetch-owner=true` adds `Owner` to each `Contents`. | BL-419 |
| S3:Surl-Listing-1 | MUST | A bad `max-keys` or a continuation token that does not decode is `400 InvalidArgument`. | BL-419 |

## Multipart uploads

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:CreateMultipartUpload-1 | MUST | `POST /<bucket>/<key>?uploads` answers `InitiateMultipartUploadResult` with `Bucket`, `Key` and `UploadId`. | BL-713 |
| S3:UploadPart-1 | MUST | `PUT ?partNumber=<n>&uploadId=<id>` stores the part and answers its `ETag`; `partNumber` outside 1 to 10000 is `400 InvalidArgument`. | BL-713 |
| S3:UploadPart-2 | MUST | An unknown `uploadId` is `404 NoSuchUpload`. | BL-713 |
| S3:CompleteMultipartUpload-1 | MUST | `POST ?uploadId=<id>` with the part list assembles the object and answers `CompleteMultipartUploadResult` with `Location`, `Bucket`, `Key` and `ETag` `"<hex>-<count>"`. | BL-713 |
| S3:CompleteMultipartUpload-2 | MUST | A part not uploaded or with another ETag is `400 InvalidPart`; parts out of order `400 InvalidPartOrder`; a part but the last below 5 MiB `400 EntityTooSmall`; a body that does not parse `400 MalformedXML`. | BL-713 |
| S3:AbortMultipartUpload-1 | MUST | `DELETE ?uploadId=<id>` discards the parts and answers `204`. | BL-713 |
| S3:Surl-Multipart-1 | MUST | Parts are invisible to every protocol until completion. | BL-713 |
| S3:Surl-Multipart-2 | MUST | 1000 open uploads at most (`503 SlowDown`); an upload idle 24 hours is aborted. | BL-713 |
| S3:ListParts-1 | MAY | `GET ?uploadId=<id>` lists the parts. | n/a: `501 NotImplemented` (ADR-0108 decision 1) |

## Authentication ("Authenticating Requests (AWS Signature Version 4)" and its signature pages)

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:Surl-Auth-1 | MUST | With anonymous off, a request with no signature is `403 AccessDenied`, with no `401` and no `WWW-Authenticate`. | BL-420 |
| S3:Surl-Auth-2 | MUST | Under `--allow-anonymous`, unsigned reads are served and unsigned writes are `403 AccessDenied`. | BL-420 |
| S3:Surl-Auth-3 | MUST | A write needs `--allow-uploads`; without it a signed write is `403 AccessDenied`. | BL-419 |
| S3:SigV4-Authorization-1 | MUST | `Authorization: AWS4-HMAC-SHA256 Credential=…,SignedHeaders=…,Signature=…` is checked; the page's worked GET-object example verifies at its date. | BL-420 |
| S3:SigV4-Authorization-2 | MUST | A header that does not parse, or a scope whose service is not `s3`, is `400 AuthorizationHeaderMalformed`. | BL-420 |
| S3:SigV4-Authorization-3 | MUST | Another `Authorization` scheme is `400 InvalidArgument`. | BL-420 |
| S3:SigV4-Credential-1 | MUST | An access key that is no account is `403 InvalidAccessKeyId`. | BL-420 |
| S3:SigV4-Signature-1 | MUST | A signature that does not verify is `403 SignatureDoesNotMatch`. | BL-420 |
| S3:SigV4-Date-1 | MUST | A request more than 15 minutes from the server's clock is `403 RequestTimeTooSkewed`. | BL-420 |
| S3:SigV4-Payload-1 | MUST | A signed request without `x-amz-content-sha256` is `400 InvalidRequest`. | BL-420 |
| S3:SigV4-Payload-2 | MUST | A body not hashing to `x-amz-content-sha256` is `400 XAmzContentSHA256Mismatch` and is not stored. | BL-420 |
| S3:SigV4-Payload-3 | MUST | `UNSIGNED-PAYLOAD` leaves the body unbound and is served. | BL-420 |
| S3:SigV4-Scope-1 | MUST | Any region in the scope is accepted. | BL-420 |
| S3:Surl-Auth-4 | MUST | The checked account is what the store's share access check receives. | BL-420 |
| S3:SigV4-SessionToken-1 | MAY | `x-amz-security-token` is accepted as a signed field and grants nothing. | BL-420 |
| S3:SigV4-QueryString-1 | MUST | A presigned URL (`X-Amz-Algorithm`, `-Credential`, `-Date`, `-Expires`, `-SignedHeaders`, `-Signature`) is checked over `UNSIGNED-PAYLOAD`. | BL-711 (`AwsSigV4PresignedAndChunkedTests.PresignedWorkedExample_AtItsDate_IsAcceptedAsTheKeysAccount`, `S3LoginTests.ServeAsync_PresignedGetObject_IsReadAsGetObjectWithItsSignatureParametersSetAside`) |
| S3:SigV4-QueryString-2 | MUST | Past `X-Amz-Date` plus `X-Amz-Expires` is `403 AccessDenied`; `X-Amz-Expires` outside 1 to 604800 is `400 InvalidArgument`. | BL-711 (`AwsSigV4PresignedAndChunkedTests`, `S3LoginTests.ErrorOf_PresignedUrlRefusals_HaveTheirErrors`) |
| S3:SigV4-Chunked-1 | MUST | `STREAMING-AWS4-HMAC-SHA256-PAYLOAD` chunks are each checked against the chained signature (`403 SignatureDoesNotMatch`), `x-amz-decoded-content-length` the object's length. | BL-711 (`AwsSigV4PresignedAndChunkedTests.ChunkedWorkedExample_SeedSignature_IsAcceptedWithAChainThatVerifiesEachChunk`, `S3ObjectBodyReaderTests.ServeAsync_ChunkedUploadWorkedExample_StoresTheDecodedObjectAndChecksEveryChunk`) |
| S3:SigV4-Chunked-2 | MUST | `STREAMING-UNSIGNED-PAYLOAD-TRAILER` is served and its trailing checksum checked. | BL-711 (`S3ObjectBodyReaderTests.ServeAsync_UnsignedTrailerWithItsCrc32_IsStoredAndTheChecksumEchoed`) |
| S3:SigV4-Chunked-3 | MAY | `STREAMING-AWS4-ECDSA-P256-SHA256-PAYLOAD` and the signed trailer forms. | n/a: `501 NotImplemented` (ADR-0108 decision 4.5) |

## TLS and limits (ADR-0108 decisions 5 and 7; ADR-0006)

| ID | Level | Requirement | Covered by |
| --- | --- | --- | --- |
| S3:Surl-Tls-1 | MUST | `s3` is implicit TLS, `--cert` or `--self-signed` required (58 without), ALPN `http/1.1` only. | BL-421 |
| S3:Surl-Tls-2 | MUST | `--s3-plaintext` serves plain HTTP/1.1 and is warned on start. | BL-421 |
| S3:Surl-Limits-1 | MUST | A head past `--max-request-head` is `400 RequestHeaderSectionTooLarge`, then close. | `S3ProtocolServerTests.ServeAsync_HeadPastMaxRequestHead_IsRefused400RequestHeaderSectionTooLargeAndClosed` |
| S3:Surl-Limits-2 | MUST | A body, part or completed object past `--max-filesize` is `400 EntityTooLarge`, then close. | BL-419 |
| S3:Surl-Limits-3 | MUST | Past `--max-connections` or `--max-connections-per-address` is `503 SlowDown`, then close. | BL-418 |
| S3:Surl-Limits-4 | MUST | `--head-timeout`, `--idle-timeout` and `--max-time` close with no bytes. | BL-418 |
| S3:Surl-Limits-5 | MUST | A full metadata index is `503 ServiceUnavailable`. | BL-419 |
